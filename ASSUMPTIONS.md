# Допущения

1. **Данные.** Официальный starter отсутствует. В комплекте собственные демонстрационные данные,
   примеры и эмулятор по описанному контракту. Они не являются персональным seed-набором заказчика.
2. **Сумма SOURCE.** `source_amount` - весь дебет клиента, включая комиссию в SOURCE.
   При TARGET-комиссии весь дебет конвертируется, а комиссия удерживается из валового результата.
3. **База комиссии.** SOURCE: процент от всего `source_amount`; TARGET: процент от валовой
   суммы после конвертации. Формула `max(percent * base / 100 + fixed, min)`.
4. **Округление.** Только целые minor units и Decimal. Комиссия округляется вверх (CEILING),
   конвертация вниз (FLOOR). Все правила собраны в `app/money.py`. Промежуточный Decimal-контекст -
   60 значащих цифр в расчётах. Вход строго с числом знаков валюты; научная нотация и JSON-number
   не принимаются. Максимум входа - 10^15 minor units, чтобы оставаться далеко от переполнения BIGINT.
5. **TARGET.** Бинарный поиск минимального числа source minor units, у которого округлённая
   прямая котировка даёт не меньше запрошенного target. Получатель получает ровно заказанную
   сумму. Если такой target нельзя получить прямым расчётом из-за дискретности валют, остаток
   показан в breakdown как `target_rounding_surplus`; в марже этот остаток не учитывается.
6. **Лимит направления.** Проверяется полный source-дебет в валюте `amount_limits.currency`,
   без предварительного округления сравниваемой суммы. Обе границы включены. При TARGET лимит
   проверяется для найденной минимальной суммы; сумма ниже минимума не повышается автоматически.
7. **Курсы.** Только свежие данные `/rates`, максимум 3600 секунд по умолчанию. Будущее время
   допускается не более чем на 60 секунд. Путь FX: минимальное число рёбер, лексикографический
   порядок валют при равной длине; прямой свежий курс приоритетнее обратного. Обратный курс -
   `1/rate`, cross - произведение. Старый прямой курс не запрещает свежий обратный/cross.
   Курс без timezone считается ошибкой конфигурации источника.
8. **Фиксация.** Котировка хранит цену, время расчёта, TTL и снимок всех FX. При резерве
   используются эти курсы, в том числе для комиссии провайдера и суточного лимита.
   Доступность провайдера проверяется на момент новой попытки; уже принятая выплата сверяется
   независимо от текущего enabled/maintenance.
9. **Провайдер.** Его лимиты применяются к сумме выплаты, пересчитанной в его валюту.
   Для расчёта стоимости principal округляется вверх до его minor unit, затем комиссия также вверх.
   Это консервативная оценка, а не дополнительное списание с клиента.
10. **Маржа.** `(client_fee_in_source - provider_fee_in_source) / source_amount * 100`.
    Минимум обязателен для каждого кандидата, включая запасных. Подходящего провайдера нет -
    NO_ELIGIBLE_PROVIDER до резерва. Профиль клиента не влияет на оценку провайдера.
11. **Суточный лимит.** Сутки UTC, а не локальные сутки клиента. Учитываются резерв + успешные
    переводы. Неуспех освобождает лимит дня создания. Переход через полночь не переносит расход.
12. **Идемпотентность.** Ключ изолирован по client_id, действует бессрочно. Тело сравнивается
    по каноническому JSON; порядок полей не важен. X-Scenario входит в отпечаток. Для нового
    ключа ранее использованная котировка даёт QUOTE_ALREADY_USED даже если она уже истекла.
13. **Контракт провайдера.** Стабильный ключ попытки гарантирует одну выплату. 422 означает,
    что выплата не принята. COMPLETED/FAILED из GET - согласованные и неизменяемые итоговые
    статусы. Reference уникален для каждой попытки, а не для всего перевода.
14. **5xx и 404.** Полный HTTP 5xx сам по себе не даёт права переключать провайдера: сначала
    GET по reference. Если у попытки не было таймаута/испорченного ответа/принятого payout_id,
    и после полного 5xx GET возвращает 404, предполагается, что payout не существует и уже
    не появится; можно пробовать запасного. Это существенное дополнительное допущение,
    явно не гарантированное PDF. Если GET может отставать или провайдер создаёт payout после
    5xx асинхронно, такой failover небезопасен: нужен более сильный контракт. См. LIMITS.md.
15. **Таймаут и 404.** После неоднозначного исхода 404 не является подтверждением отказа.
    Повторяется POST тому же провайдеру с тем же ключом. Резерв остаётся до подтверждённого
    результата; после 120 секунд ставится NEEDS_REVIEW, автоматическая сверка продолжается.
16. **Webhook.** Подписанное событие - сигнал проверить GET. Оно не списывает деньги само.
    Это позволяет пережить дубли и перестановку событий. Неизвестные reference сохраняются
    для аудита и получают 202, но не создают выплату. Старые события не меняют итог перевода.
17. **Баланс.** Начальные балансы загружаются только для отсутствующих записей. Правки
    clients.json не пополняют существующие счета и не меняют существующие лимиты клиентов.
    Пополнения, возврат после успешной выплаты и изменение клиента через API не входят в задачу.
