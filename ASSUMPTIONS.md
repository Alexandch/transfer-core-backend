# Допущения

1. SOURCE - полный дебет клиента, включая SOURCE-комиссию. При TARGET-комиссии весь дебет
   конвертируется, а комиссия удерживается из валового результата.
2. Комиссия: max(percent * base / 100 + fixed, min). SOURCE-база - source_amount,
   TARGET-база - валовая сумма после конвертации.
3. Все суммы хранятся в целых minor units, ставки и промежуточные расчёты используют Decimal.
   Комиссии округляются CEILING, конвертация FLOOR. Правила собраны в money.py.
   Денежный ввод - строка с точным числом знаков валюты; максимум 10^15 minor units.
4. TARGET ищет минимальный source, прямая округлённая котировка которого покрывает заказ.
   Выплата ровно заказанная. Дискретный избыток отражён как target_rounding_surplus и не повышает
   расчётную маржу. Сумма ниже минимума направления автоматически не увеличивается.
5. Лимит направления проверяется по полному source-дебету в валюте amount_limits.currency,
   без предварительного округления сравниваемой суммы. Обе границы включены.
6. Курс берётся из /rates; свежесть по умолчанию 3600 секунд, допустимое будущее время - 60 секунд.
   Прямой свежий курс приоритетнее обратного. Для cross выбирается кратчайший путь,
   при равной длине - лексикографический порядок валют. Обратный курс - 1/rate.
7. Котировка фиксирует цену, FX-снимок и TTL. При резерве снимок используется также для
   стоимости провайдера и суточного лимита. Истёкшую котировку можно читать, но нельзя использовать.
8. Лимиты провайдера относятся к principal выплаты в его валюте. Principal и стоимость комиссии
   округляются вверх в его minor units для консервативной оценки расходов.
9. Маржа = (client_fee_in_source - provider_fee_in_source) / source_amount * 100.
   Минимум обязателен для каждого провайдера, включая запасного.
10. Суточный лимит - UTC-день создания перевода, резерв + успех. Отказ освобождает лимит этого дня.
11. Idempotency-Key изолирован по client_id и хранится бессрочно. Канонический JSON исключает
    влияние порядка полей; X-Scenario входит в отпечаток. Котировка расходуется один раз.
12. Провайдер сохраняет идемпотентность одного ключа. 422 означает явное непринятие запроса.
    5xx, таймаут и 404 не являются доказательством отказа. Повторяется прежняя попытка.
    Без окончательного ответа сохраняется резерв и выставляется NEEDS_REVIEW.
13. Авторитетный GET должен в итоге сообщать фактический исход. Одиночный FAILED подтверждается
    повторно; конфликт с подписанным COMPLETED или другим payout_id блокирует failover.
    Терминальные статусы сервиса не пересчитываются финансово по позднему webhook.
14. Подписанный webhook - долговечный сигнал к сверке. Дубли дедуплицируются, неизвестные reference
    сохраняются без создания перевода. Тело с прежним event_id и другим содержимым даёт конфликт.
15. providers.json читается без редеплоя. План при резерве сохраняется; перед каждой новой попыткой
    фильтры и оценки пересчитываются с текущим конфигом и FX-снимком котировки. Результаты
    сохраняются в selections. Начальные балансы существующих клиентов не сбрасываются.
16. Демонстрационный /rates публикует значения rates.json со свежим временем. Это тестовый источник.
    error_5xx сохраняет окончательный отказ выплаты, возвращает 503 и сообщает FAILED при GET.
