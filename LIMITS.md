# Ограничения

- Данные, примеры и эмулятор созданы по контракту задания. Результаты относятся к этому набору;
  индивидуальный исходный starter отсутствует.
- Согласованность с внешним провайдером требует сохранения им идемпотентности и достоверного
  окончательного GET. Произвольная ложь провайдера после подтверждённого терминального отказа
  не может быть устранена локальной транзакцией. Обнаруженные противоречия сохраняются для проверки;
  автоматического повторного финансового расчёта завершённого перевода нет.
- При недоступном провайдере NEEDS_REVIEW сохраняет резерв до подтверждения исхода.
  Срок ожидания не является разрешением выплатить через другого провайдера или вернуть средства.
- Конфигурационные файлы заменяются атомарно. Провайдеры валидируются при чтении;
  неверная конфигурация даёт CONFIG_INVALID, не освобождая уже зарезервированные деньги.
- API предназначен для локального запуска задания. Аутентификация клиента, пополнения,
  возвраты успешных выплат и частичные выплаты не входят в реализуемый контракт.
- Метрики с transfer_id имеют растущую кардинальность; хранение истории и ключей не ограничено.
  Нагрузочные числа характеризуют локальную среду и не являются производственным SLA.
