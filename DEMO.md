# Демонстрационный прогон

При первом запуске в PostgreSQL есть клиенты и начальные балансы из starter, а переводов нет.
Демонстрационные операции создаются отдельно и сохраняются между перезапусками приложения.

## Запуск

```sh
docker compose up --build
```

Во втором терминале:

```sh
docker compose --profile demo run --rm demo
```

Команда создаёт через API четыре перевода клиента c_101: ok, decline, error_5xx и slow.
Slow использует TARGET; остальные - SOURCE. Каждый повторяется с тем же ключом,
а затем проверяются конфликт ключа с другим телом, выплаты по ledger, баланс и данные Prometheus.
Прогон занимает около 40 секунд. Новый запуск создаёт ещё четыре перевода.

Итог обычного прогона: два COMPLETED, два FAILED, резерв возвращается в ноль,
spent увеличивается на 20000.00 RUB. JSON-вывод содержит transfer_id, историю наблюдавшихся
статусов, выбранных провайдеров и баланс до/после.

Локальный вариант с сохранением отчёта:

```sh
uv run python scripts/demo_run.py --json output/demo.json
```

Демо и другие генераторы операций для одного клиента запускаются последовательно.
При ALLOW_SCENARIOS=false демонстрационные X-Scenario недоступны.

## Просмотр

- Prometheus: http://127.0.0.1:9090/query — ввести запрос и выбрать Graph.
- Targets: http://127.0.0.1:9090/targets — transfer-core должен иметь состояние UP.
- JSON-счётчики: http://127.0.0.1:8080/stats.
- API и просмотр перевода по transfer_id: http://127.0.0.1:8080/docs.

В Prometheus данные снимаются раз в 5 секунд. На графике с диапазоном 15 минут видны
создание переводов, временный резерв и окончательное списание. Число переводов в чистой базе
отображается нулём даже до первого демо.

Запросы перечислены в [monitoring/QUERIES.md](monitoring/QUERIES.md).
Финансовая история находится в PostgreSQL; история графиков хранится в отдельном томе Prometheus 7 дней.
